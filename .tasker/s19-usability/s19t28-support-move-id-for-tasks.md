# Support move --id for tasks rename

To manually resole conflicts it's good to be able to change task id, by specifying any new value that is not occupied.
Note that is should still follow all existing rules for id naming convention, but only that. If id is free, then just update it (recursively, same as renames when moving a task to another root).
